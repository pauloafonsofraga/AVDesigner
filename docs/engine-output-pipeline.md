# Engine Output Pipeline

Current build label: `Iteration 51`

Iteration 51 adds a canonical runtime output snapshot in front of reports,
PDF export, self-contained HTML export, and hosted viewer publish. The snapshot
is runtime-only and does not change the `.avd` save format.

## Supported Output Types

The Legacy output inventory for commit
`8301fbf23c82f3e3f2496cb90234019c7bf47958` contains these user-facing output
paths:

- editor project report popup, launched by `projectReportButton`
- print/PDF report flow, launched by `exportPdf`
- self-contained interactive HTML viewer download, launched by `exportHtml`
- hosted/password-protected technician viewer publish, launched by
  `publishProjectButton`

No separate CSV/BOM export entrypoint was found in the audited Legacy output
button/function paths. Cable, device, LED, power, rack, and matrix summaries are
part of the report data generated by `buildProjectReport`.

## Legacy Rendering Dependencies Found

- `openEditorReport` was data/report driven.
- `exportHtml` and `publishHostedProject` serialized project data and generated
  a standalone viewer.
- `exportPdfReport` depended on `wirechartSvgMarkup`.
- `wirechartSvgMarkup` cloned the live production SVG canvas, then ran print
  cleanup/light-mode fixes and wire-visual injection.

Iteration 51 keeps that PDF visual dependency in place intentionally, but the
entrypoint now receives canonical snapshot bounds and records the dependency in
snapshot metadata. This gives the next pass one place to replace the clone with
a data-driven output renderer.

## Snapshot Contract

The output snapshot records:

- project data clone
- export bounds
- report data
- device, wire, connector, rack, LED, area, comment, title block, and jump-node counts
- rack internal wire records
- rack exposed-port visibility/selectability diagnostics
- asset counts before and after inline embedding
- orphan endpoint, duplicate wire ID, non-finite bounds, and rack-wire warnings
- generation timings for snapshot/report/bounds/asset-inline/PDF SVG/HTML/PDF

The output snapshot must not depend on:

- current pan or zoom
- WebGL viewport culling
- selected, hovered, or dragged object state
- debug/HUD overlays
- visible-only canvas rendering

## Current Rendering Split

Reports already read semantic project data. The self-contained technician viewer
also uses embedded project data and its own viewer renderer.

The remaining high-risk dependency is PDF wirechart drawing:
`wirechartSvgMarkup` still clones the Legacy SVG canvas, then injects missing
wire strokes for the print path. Iteration 51 does not replace that renderer;
it wraps the call with canonical snapshot bounds, report data, diagnostics, and
timing so a later pass can replace the clone with a data-driven SVG/PDF renderer
without changing the export entrypoints.

## Output Bounds

Iteration 51 continues to use the audited Legacy bounds helper,
`wirechartExportBounds`. That helper combines:

- object bounds from the project object collections
- comment anchors and comment boxes
- self-patch connection bounds
- rack bounds
- `80px` export padding

The bounds do not use current pan, zoom, browser size, sidebar width, DPR, or
WebGL camera state.

## Output Layer Order

The standalone viewer defines explicit SVG groups in this order:

1. areas
2. racks
3. wires
4. LED surfaces
5. devices
6. jump nodes
7. comments
8. hover/magnified info boxes

The PDF path still inherits the production SVG ordering from the cloned canvas,
with print-specific cleanup applied afterward. Matching this order in a
data-driven PDF renderer is the next parity step.

## Connector And Rack Rules

The snapshot records effective connector diagnostics from resolved templates
and instance overrides. Rack child connector diagnostics distinguish:

- visible exposed rack ports
- selectable exposed rack ports
- rack-internal-only connectors when internal wiring is shown
- hidden rack child connectors

Rack internal wires are recorded separately from normal project cables and are
marked as orthogonal/non-selectable derived output records.

LED surfaces keep the `{ surfaceId }` endpoint architecture and should not
produce synthetic connector records.

## Diagnostics

Open the app with:

```text
index.html?debugOutput=1&v=iteration51
```

or:

```text
index.html?legacy=1&debugOutput=1&v=iteration51
```

Then run:

- Project Report
- Export PDF
- Export HTML
- Publish Viewer Link

The Output Debug panel shows snapshot counts, bounds, timings, assets, and
warnings. Exported HTML can also be opened with `?debugOutput=1` to show the
embedded snapshot metadata in the technician viewer.

## Known Gap

Full output parity is not yet proven until the PDF wirechart renderer no longer
depends on cloning the editor SVG. That final swap must visually compare:

- devices and faceplates
- modular cards
- adapters/breakouts
- LED surfaces
- areas
- comments
- title blocks
- jump nodes
- racks and internal rack wiring
- cable hops
- Bezier and orthogonal custom routes
