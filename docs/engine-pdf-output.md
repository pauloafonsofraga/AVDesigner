# Engine PDF output and Jump navigation

## Production status

`exportPdfReport()` still produces a one-step, vector PDF through the Engine SVG
and Chromium print path. The printable report builder still owns the drawing,
Devices, Adapters / Breakouts, Racks, LED Screens, Cable Schedule and Matrix
Routing sections. Its drawing does not use the Legacy canvas or an SVG clone.

Clickable Jump links are temporarily **disabled** in production. Chromium's
fragment-link destinations can land at incorrect coordinates when paper,
margin or print scale changes. The Engine serializer no longer emits invisible
SVG anchors, so the production PDF has no broken clickable areas. It still
renders Jump rings and labels and the physical wires to them, while suppressing
the virtual Jump Link path. HTML and Publish continue to use their existing
interactive Engine viewer behavior. The canonical scene and its signature are
unchanged. PDF diagnostics report `jumpNavigationCandidates`, zero
`jumpDestinations`, zero `jumpAnnotations`, and zero `visibleJumpLinkPaths`.

`src/engine/outputNavigation.js` extracts reciprocal, valid Jump pairs and
their logical Engine bounds as immutable data. It rejects missing, self-paired,
duplicate and non-finite endpoints. Its codepoint-encoded destination IDs are
stable even for punctuation and non-BMP characters. It contains no print or
browser coordinates.

## Developer-only finalizer

`scripts/pdf-jump-reference.mjs` can add reference SVG links to a test drawing;
the production renderer does not call it. `scripts/finalize-pdf-jumps.py` reads
a reference PDF and a per-page Engine navigation manifest, locates the actual
finished-PDF annotation rectangles, and rewrites each `/GoTo /XYZ` destination
to the paired annotation's page and top-left. It preserves zoom with a null
zoom value. It does not solve CSS/print coordinates again or alter page paint.
Missing, duplicate or unexpected links fail before writing output. This is a
reference tool, not a user export or a second-download workflow.

## Experimental app-owned backend

`src/engine/outputPdfPrototype.js` uses pinned PDFKit 0.20.2 and
SVG-to-PDFKit 0.1.8. It consumes the existing Engine SVG (including vector
plug artwork expanded from inline SVG image wrappers) and canonical report
rows. It does not recreate device/wire layout. `outputPdfLayout.js` owns A4,
A3, A2 and A1 paper, portrait/landscape, millimeter margins, Fit and 1-100%
of Fit scaling. The one `pdfPageLayout()` transform places the drawing and maps
both source hit rectangles and target named destinations. `/GoTo` links are
internal, reciprocal and point at the paired node's page/top bounds; `/XYZ`
retains the reader's zoom. Drawing pages may be separately imposed for a
cross-page Jump pair. The browser entry is query-gated by `?experimentalPdf=1`
and downloads one PDF; the normal Export PDF command is unchanged. The
experimental bundle is generated by `npm run build:pdf-prototype` and checked
by `npm run check:pdf-prototype`.

The experimental report includes the same section categories and grouped
Cable Schedule fields (Qty, Cable Type, Length), with repeated table headers
and row-boundary pagination. It is **not production-ready**. Raster comparison
shows a different drawing background/frame and text weight/size from Chromium,
and the report tables do not yet match the production typography, widths and
matrix grid. Full visual/report parity and large-project performance must be
accepted before replacing production. Do not promote this backend solely on
structural navigation success.

## Verification

Run from the repository root with a local server at `http://127.0.0.1:8768`:

```sh
node --test test/outputPdfJumps.test.mjs test/outputPdfPrototype.test.mjs test/outputSvgRenderer.test.mjs
node scripts/engine-output-pdf-smoke.mjs
python3 scripts/inspect-engine-output-pdf.py <production-artifact-directory>
node scripts/engine-pdf-finalizer-smoke.mjs
node scripts/engine-pdf-prototype-smoke.mjs <production-artifact-directory>
python3 scripts/inspect-pdf-prototype.py <prototype-artifact-directory>
node scripts/engine-pdf-prototype-browser-smoke.mjs
node scripts/engine-pdf-prototype-click-smoke.mjs <prototype-artifact-directory>
npm run check:pdf-prototype
```

The production smoke exports a real Chrome PDF, checks vector/scene parity,
preserved report sections, a 100-device/300-cable report and a managed Loom.
The inspector requires zero Jump link annotations and no URI action. The
prototype test matrix covers A4/A3/A2 paper, 0/4/10 mm margins, 75%/100%
of Fit, wide/tall drawings, strict/bidirectional pairs, unpaired nodes and a
cross-page pair. `inspect-pdf-prototype.py` verifies PDF annotation rectangles
and `/XYZ` destinations against the exact app-owned transform and page refs.
The offline Chrome PDFium click harness exercises reciprocal navigation at
300% zoom. Browser interaction in Preview and Acrobat is not yet verified.

Test artifacts are generated in temporary directories, not committed. The
prototype is isolated from HTML/Publish, saved projects, the canonical scene
signature and the supported Legacy application mode.
